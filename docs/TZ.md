# Техническое задание (ТЗ) — Root Access

## 1. Наименование и цель проекта
- **Название:** Root Access
- **Цель:** Разработать детективную игру-симулятор исследования ноутбука серийного маньяка с нелинейными загадками и несколькими концовками на движке Godot 4.

## 2. Стек и архитектура
- **Движок / Язык:** Godot 4.x / GDScript (`Control`-ноды для UI виртуальной ОС).
- **Архитектурный подход:** Разделение UI-сцен, ядра и контента загадок:
  - `scenes/` — отдельные сцены для каждого приложения виртуальной ОС (рабочий стол, проводник, галерея, терминал, заметки, концовки).
  - `scripts/core/` — менеджер состояния игры (`GameState`), виртуальная ФС (`VFS`: `list_dir`, `read_file`, `decrypt_file`), триггеры концовок.
  - `data/` — JSON-файлы с контентом загадок (`files.json`, `notes.json`, `endings.json`, метаданные фото).
  - `assets/` — изображения (фото-улики, иконки, обои), шрифты и звуки.

## 3. Этапы и календарный план разработки (7 пар разработки + защита)
1. **Пара 1 (Организационный этап, выполнено):** Определение ролей команды, настройка Git-репозитория (`main`/`dev`, Issues, Kanban), разработка `SRS.md` и `TZ.md`.
2. **Пара 2 (Каркас Godot 4 и Use Case диаграмма):** Инициализация проекта Godot, архитектура ядра (`GameState.gd`), окно рабочего стола (`Desktop.tscn`), каркас окон (`WindowFrame.tscn`), сцена терминала (`Terminal.tscn`), составление Use Case диаграммы.
3. **Пара 3 (Проводник, Галерея и Диаграмма состояний):** Контроллер VFS, навигация по папкам («Проводник»), приложение «Галерея» с просмотром фото, базовые команды терминала (`help`, `ls`, `cd`, `pwd`, `clear`), составление State Diagram.
4. **Пара 4 (Ключевой пазл фото-пароль, Заметки и Sequence-диаграмма):** Окно свойств фото (извлечение даты съемки для разгадки пароля), модальный диалог ввода пароля, приложение «Заметки» с PIN-замком и подсказками к терминалу, составление Sequence-диаграммы.
5. **Пара 5 (Дешифровка в терминале, улики и Activity/BPMN диаграмма):** Реализация команды `decrypt <файл> -k <ключ>`, чтение и дешифровка файлов улик `.enc`, команды `cat`, `find`, `history`, составление Activity/BPMN диаграммы расследования.
6. **Пара 6 (Концовки сюжета, полировка и DFD-диаграмма):** Реализация логики 3+ концовок в `GameState`, оформление экранов концовок, системные звуки и пасхалки терминала, составление DFD-диаграммы потоков данных.
7. **Пара 7 (Комплексное тестирование QA, экспорт билда и подготовка слайдов):** Сквозное тестирование сценариев и концовок, составление таблицы тест-кейсов `docs/TESTS.md`, исправление дефектов, сборка готового дистрибутива игры, оформление презентации.
8. **Пара 8 (Защита проекта):** Демонстрация живого геймплея игры, защита проекта по слайдам презентации.

## 4. Критерии приёмки
- Полная проходимость основной сюжетной цепочки (от поиска пароля по фото и работы в заметках/терминале до финала).
- Наличие минимум 3 рабочих концовок.
- Отсутствие критических ошибок при запуске собранного проекта.
- Наличие документации (`SRS`, `TZ`, `README`), UML-диаграмм и истории коммитов всех участников.
