# Техническое задание (ТЗ) — Root Access

## 1. Наименование и цель проекта
- **Название:** Root Access
- **Цель:** Разработать детективную игру-симулятор исследования ноутбука серийного маньяка с нелинейными загадками и несколькими концовками на движке Godot 4.

## 2. Стек и архитектура
- **Движок / Язык:** Godot 4.x / GDScript (`Control`-ноды для UI виртуальной ОС).
- **Архитектурный подход:** Разделение UI-сцен, ядра и контента загадок:
  - `scenes/` — отдельные сцены для каждого приложения виртуальной ОС (рабочий стол, проводник, галерея, терминал, заметки, концовки).
  - `scripts/core/` — менеджер состояния игры (`GameState`), виртуальная ФС (`VFS`: `list_dir`, `read_file`, `decrypt_file`), триггеры концовок.
  - `data/` — JSON-файлы с контентом загадок (`files.json`, `notes.json`, `endings.json`, метаданные фото).
  - `assets/` — изображения (фото-улики, иконки, обои), шрифты и звуки.

## 3. Этапы и календарный план разработки
1. **Этап 1 (1-я пара):** Определение ролей, настройка GitHub (ветки `main`/`dev`, Issues, Kanban), подготовка `SRS.md` и `TZ.md`.
2. **Этап 2:** Прототип проекта на Godot — каркас рабочего стола в стиле Windows 98, оконной системы, базового `GameState` и VFS из JSON.
3. **Этап 3:** Реализация приложений «Проводник», «Галерея (свойства фото)», «Заметки» и «Терминал» с парсером команд.
4. **Этап 4:** Наполнение сюжетным контентом (улики, фото, команды), реализация цепочек загадок и системы концовок.
5. **Этап 5:** Тестирование (таблица тест-кейсов), исправление багов, сборка, подготовка UML-диаграмм и финальной презентации.

## 4. Критерии приёмки
- Полная проходимость основной сюжетной цепочки (от поиска пароля по фото и работы в заметках/терминале до финала).
- Наличие минимум 3 рабочих концовок.
- Отсутствие критических ошибок при запуске собранного проекта.
- Наличие документации (`SRS`, `TZ`, `README`), UML-диаграмм и истории коммитов всех участников.
